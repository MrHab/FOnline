# Архитектура

## Общий принцип

Проект разделён на клиент и сервер.

Клиент отвечает за:
- визуализацию Three.js;
- управление игроком;
- интерфейс;
- локальные эффекты;
- отображение серверного состояния.

Сервер отвечает за:
- авторизацию;
- серверные данные персонажей;
- комнаты и локации;
- положение игроков;
- врагов;
- лут;
- контейнеры;
- проверку дистанций, урона, лечения и переходов.

## Правило MMO

Если сущность видят несколько игроков, её состояние должно быть серверным. Клиент не должен сам решать, жив ли враг, есть ли лут в контейнере или подобран ли предмет с земли.

## Основные файлы

```text
server.js                         основной сервер
src/server/authoritative-server.js подготовленная серверная логика
public/index.html                  HTML-контейнер игры
public/css/game.css                сборщик CSS-частей
public/css/game/*.css              модульные CSS-файлы
public/js/game.js                  загрузчик клиентских JS-частей
public/js/game/*.js                модульные клиентские JS-файлы
docs/wiki/                         актуальная документация проекта
```

## Клиентский загрузчик

`public/js/game.js` загружает части клиента из `public/js/game/`. Проверка сборки выполняется скриптом `tools/check-client-js.js`, который реконструирует клиентский бандл и проверяет синтаксис.

## CSS

`public/css/game.css` подключает модульные CSS-файлы. Проверка выполняется через `tools/check-client-css.js`.

## Сетевой цикл

1. Игрок входит в аккаунт.
2. Клиент подключается к Socket.IO.
3. Сервер помещает игрока в комнату локации.
4. Клиент отправляет `input` и действия.
5. Сервер рассылает snapshots игроков, врагов, предметов и контейнеров.
6. Клиент отображает только подтверждённое сервером состояние.
