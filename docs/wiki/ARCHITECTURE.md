# Архитектура

Production-приложение — один Node.js-процесс из `server.js`, который обслуживает
REST API, Socket.IO и статику, включая Unity WebGL-сборку. В production статику
рекомендуется отдавать напрямую через Nginx.

Игровой клиент — Unity-проект `unity-client/`. Он подключается к серверу как
обычный HTTP + Socket.IO клиент и не содержит собственной авторитетной игровой
логики.

## Слои

| Слой | Основные файлы | Ответственность |
|---|---|---|
| HTTP и realtime | `server.js` | auth, персонажи, комнаты, игровой мир, Socket.IO |
| Серверные подсистемы | `src/server/*.js` | живая пустошь, AI, активности, collider-геометрия, NPC-инвентарь |
| Сетевой слой клиента | `unity-client/Assets/Scripts/Net/` | HTTP-авторизация, собственный Socket.IO-транспорт, join/reconnect-FSM |
| Мир клиента | `unity-client/Assets/Scripts/World/` | координаты, загрузка локаций из JSON/GLB, terrain, глобальная карта |
| Игровой слой клиента | `unity-client/Assets/Scripts/Game/` | персонажи, бой, UI-канвы, fog-of-war, глобальная карта, мобильное управление |
| Авторские данные | `data/*.json`, `data/locations/*.json` | карта, локации, квесты, встречи, экономика |
| Общие модели | `public/assets/models/` | GLB, которые без конвертации грузят оба клиента |
| Runtime-данные | `DATA_DIR/*.json` | аккаунты, персонажи, состояние симуляции |
| Инструменты | `tools/*.js`, `unity-client/Tools/` | генераторы, проверки, сборка клиента |
| Legacy web-клиент | `public/index.html`, `public/js/` | доступен по `/legacy/`, не развивается, источник parity-проверки |

Единственный серверный entry point — `server.js`. Модули `src/server/*.js`
активны только когда явно импортированы из него; отдельной копии сервера в
`src/server/` нет.

## Запуск Unity-клиента

1. `RoaGameBootstrap` поднимает экран входа (`RoaAuthCanvas`): вход,
   регистрация, восстановление пароля или гостевой быстрый старт через
   `RoaAuthClient` (REST).
2. После выбора или создания персонажа клиент выполняет единственный
   Socket.IO `join` для текущего поколения соединения с `token`, `deviceId`,
   `clientInstanceId`, `characterId` и `enemyFrameVersion: 1`.
3. Ack `join` возвращает `characterLeaseId`, комнату, собственное авторитетное
   состояние, список игроков и `worldState`.
4. `RoaLocationLoader` собирает сцену из авторского JSON локации и GLB
   (glTFast), `RoaLocalTerrain` строит землю и коллизии по авторитетной
   `worldState.map`, затем создаётся игрок. Всё происходит под полноэкранной
   загрузкой (`RoaLoadingCanvas`).
5. Таймаут `join` — 5000 мс; просроченный callback игнорируется, соединение
   уходит в управляемый reconnect. До нового ack игровой authority считается
   потерянным: движение, бой и взаимодействия блокируются, отдельной
   offline-симуляции у Unity-клиента нет.
6. Пакеты чужой комнаты отбрасываются по `roomId`: во время перехода между
   локациями в полёте остаются сообщения предыдущей сцены.

Сетевой транспорт — собственная реализация Engine.IO v4 / Socket.IO v5 поверх
`System.Net.WebSockets` (`Net/SocketIo/`). В WebGL тот же протокол работает
через мост `Assets/Plugins/WebGL/RoaWebSocket.jslib` к браузерному WebSocket;
игровой слой (`RoaSocketClient`) не меняется.

## HTTP-контур

REST используется для:

- регистрации, входа, гостевого входа, heartbeat, выхода и восстановления
  пароля;
- списка, чтения, синхронизации и удаления персонажей;
- получения локаций, квестов, глобальной карты и публичного состояния пустоши;
- локальных dev-редакторов мира, по умолчанию закрытых и доступных только через
  явно выбранный `DEV_API_MODE=local|token`;
- `/health`.

Bearer token привязан к `deviceId` (Unity хранит его в `PlayerPrefs`). Для
чтения и записи активного персонажа клиент также передаёт `clientInstanceId` и
выданный сокетом `characterLeaseId`. Сессия продлевается десятисекундным
heartbeat; logout сначала просит сервер завершить сессию и освободить
блокировки.

## Realtime-контур

Socket.IO обслуживает движение, действия и общие сущности комнаты:

1. Single-flight `join` проверяет account session и блокировку персонажа;
   повтор той же identity на уже присоединённом socket идемпотентно возвращает
   текущее состояние (`alreadyJoined: true`).
2. `state` передаёт актуальный movement proposal; `seq` строго растёт, пакеты
   с не большим `seq` сервер молча отбрасывает. Начало и остановка движения
   отправляются немедленно, промежуточные координаты — не чаще 20 Гц.
3. Частый volatile `playerState` передаёт движение других игроков; отбрасывать
   устаревшие по `seq` пакеты обязан клиент.
4. Полный `snapshot` периодически сверяет состав и статус игроков комнаты.
5. NPC синхронизируются двумя потоками: надёжный `enemySnapshot` задаёт состав,
   компактный volatile `enemyFrame` двигает уже известных акторов.
6. Действия с боем, лутом, торговлей и миром подтверждаются ack-ответом, после
   чего сервер рассылает изменившееся общее состояние. Любой `EmitWithAck`
   Unity завершается ответом, локальным таймаутом или отказом из-за разрыва
   связи — интерфейс не остаётся навсегда в ожидании.

Обычный `ack.self` сверяет параметры, инвентарь и HUD, но не переставляет
локального игрока по `x/z`. Координаты применяются явно при `join`, переходе
между локациями либо по `authoritativePlayerState` с причиной
`movementCorrection`.

## Серверная авторитетность

Сервер хранит и проверяет:

- координаты, комнату, HP/AP, прогрессию и экипировку игроков;
- серверный инвентарь, вес, быстрые предметы и состояние оружия;
- NPC, их снаряжение, боеприпасы, AI, трупы и лут;
- предметы на земле, ресурсы, контейнеры, торговые запасы и хранилища;
- глобальные маршруты, встречи, отряды, задания и фракционные изменения;
- допустимость дистанции, LOS, коллизий и переходов.

Клиент отвечает за input, предсказание движения, анимацию, интерфейс и
fog-визуализацию. Подробности:
[авторитетные правила](SERVER_AUTHORITATIVE_RULES.md).

## Два масштаба мира

Локальная комната — физическая 3D-локация с игроками, NPC и объектами.
Глобальная пустошь — отдельная серверная симуляция поселений, ресурсов,
инфраструктуры, караванов и конфликтов. Сервер связывает уровни через
`globalTravel*`, `serverWorldTransfer`, world zones и уникальные экземпляры
точек.

Чистые правила скорости и состава мировых отрядов находятся в
`wasteland-party-speed.js` и `wasteland-party-membership.js`. Состояние и
порядок simulation tick остаются внутри `wasteland-sim.js`.

Симуляция может жить без открытой 3D-комнаты. Пустые обычные комнаты не должны
постоянно выполнять полный локальный AI; исключения — короткое settle-окно,
активный realtime-бой и ожидающий выхода onsite-отряд.

На клиенте этим масштабам соответствуют две сцены: `Wasteland.unity`
(локальные локации) и `GlobalMapAuthored.unity` (глобальная карта);
`RoaGlobalMap` ведёт серверный маршрут, территории и живой слой пустоши.

## Данные и запись

- Авторские JSON загружаются из репозитория даже при внешнем `DATA_DIR`, если
  runtime-копии отсутствуют.
- `users.json`, `saves.json` и `wasteland-sim.json` записываются атомарно.
- При старте членство игроков в отрядах из `wasteland-sim.json` сверяется с
  активными принятыми работами, account/character identity и фракциями
  персонажей из `saves.json`.
- Нечитаемые runtime JSON копируются как `*.corrupt-*` перед использованием
  fallback-структуры.
- Генерируемые GLB и `model-colliders.json` обновляются только соответствующими
  инструментами.

HTTP-сохранение активного персонажа (`POST /api/characters/:id/save`)
принимается только с действующей lease активной игровой сессии; авторитетные
поля (инвентарь, бой, прогрессия, позиция) клиентская копия перезаписать не
может. Logout и смена персонажа сначала завершают серверную сессию и только
затем закрывают соединение.

## Проверки

```bash
npm run check:server
npm run check:unity-parity
npm run check:world-party
npm run check:data
npm run smoke
npm run check
```

Smoke-проверка запускает изолированный сервер на временном порту и временном
`DATA_DIR`, проверяет REST, статику, Socket.IO и жизненный цикл нескольких
персонажей без доступа к production-данным.

Unity-клиент проверяется без редактора компиляционным прогоном
`unity-client/Tools/compile-check.ps1`, а в редакторе — детерминированными
пробами меню **Realm of Ashes** и batch-аудитом
`RealmOfAshes.EditorTools.RoaClientAuditRunner.Run`.
