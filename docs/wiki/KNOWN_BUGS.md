# Известные проблемы и технический долг

## Production-сервер остаётся крупным

[`server.js`](../../server.js) — единственная production entry point и остаётся
файлом примерно на 23 тысячи строк. Историческая неиспользуемая копия сервера
удалена, поэтому проверки больше не могут пройти на дублирующемся коде вместо
runtime. Дальнейшее разбиение должно небольшими шагами переносить независимые
системы из `server.js` в реально импортируемые модули `src/server/`.

## Legacy web-клиент как parity-источник

Прежний Three.js-клиент (`public/js/`, ~50 тысяч строк) остаётся в репозитории
как источник правды для `npm run check:unity-parity` и запасной вход
`/legacy/`. Он не развивается, но пока участвует в общем `npm run check`
(`check:client*`, `check:css`). Это двойная стоимость поддержки: изменение
серверного протокола требует синхронного обновления обоих клиентских
контрактов, пока legacy-слой не будет окончательно выведен.

## Общий building framework ещё не завершён

Текущий authored renderer загружает отдельные объекты и умеет пакетировать
модульные стены, полы и крыши, но в авторских данных пока нет завершённого
контракта здания с volumes, portals и indoor-сущностями. Старый процедурный
прототип здания торговца удалён из runtime и не должен использоваться как
fallback.

Новые здания нужно описывать через `realm.location.v1`, явные
`vision`/`collision`-правила и серверно-авторитетные интерактивные сущности.
Отдельный параллельный построитель для конкретной локации вернёт уже удалённое
расхождение между визуалом, LOS и коллизиями.

## WebGL-поставка проверена не полностью

Unity WebGL-сборка проверена в desktop Chrome и в эмуляции мобильного
устройства, но не на реальном телефоне; https/brotli на production-домене,
длинные сессии (рост памяти JS-кучи), ввод с клавиатуры в `InputField` и SDK
игровых площадок остаются непроверенными. Список — в разделе «WebGL-сборка»
[`docs/UNITY_PORT.md`](../UNITY_PORT.md).

## Кириллический путь проекта и batch-сборка

Unity 6000.5.8f1 на Windows при batch-сборке напрямую из пути с кириллицей
теряет связь `MonoScript` со сценой и упаковывает player с отсутствующими
компонентами, ошибочно завершая сборку с `Result: Success`. Поэтому
`unity-client/Tools/build-windows.ps1` обязан сначала импортировать чистую
копию проекта в ASCII-путь; сборщик считает сообщения
`Script attached ... is missing` фатальными.

## Документация дрейфует между тремя источниками

Технические описания Unity-клиента живут в `unity-client/README.md`,
`docs/UNITY_PORT.md` и этой wiki. UNITY_PORT.md исторически накапливает
разделы патч-статей (4.7–5.4) вместо чистого архитектурного документа, а
численные детали (границы зума, счётчики проб) в README быстро устаревают.
Актуальными следует считать код и wiki; при расхождении сверяться с кодом.

План устранения долга и критерии готовности перечислены в
[ROADMAP.md](ROADMAP.md).
