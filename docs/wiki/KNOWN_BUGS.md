# Известные проблемы и технический долг

## Production-сервер остаётся крупным

[`server.js`](../../server.js) — единственная production entry point, файл более
чем на 34 тысячи строк рядом с модулями `src/server/`. Дальнейшее разбиение
должно небольшими шагами переносить независимые системы из `server.js` в реально
импортируемые модули `src/server/`.

Файл продолжает расти: каждая фичевая ветка добавляет в него сотни строк. При
параллельной работе нескольких агентов в одном чекауте он же становится главным
источником конфликтов — правки в нём стоит делать мелкими и сразу коммитить.

## Общий building framework ещё не завершён

Загрузчик локаций собирает отдельные объекты и умеет пакетировать модульные
стены, полы и крыши, но в авторских данных пока нет завершённого контракта
здания с volumes, portals и indoor-сущностями.

Новые здания нужно описывать через `realm.location.v1`, явные
`vision`/`collision`-правила и серверно-авторитетные интерактивные сущности.
Отдельный параллельный построитель для конкретной локации даёт расхождение между
визуалом, LOS и коллизиями.

## WebGL-поставка проверена не полностью

Unity WebGL-сборка проверена в desktop Chrome и в эмуляции мобильного
устройства, но не на реальном телефоне; https/brotli на production-домене,
длинные сессии (рост памяти JS-кучи), ввод с клавиатуры в `InputField` и SDK
игровых площадок остаются непроверенными. Список — в разделе «WebGL-сборка»
[`docs/UNITY_PORT.md`](../UNITY_PORT.md).

## Кириллический путь проекта и batch-сборка

Unity 6000.5.8f1 на Windows при batch-сборке напрямую из пути с кириллицей
теряет связь `MonoScript` со сценой и упаковывает player с отсутствующими
компонентами, ошибочно завершая сборку с `Result: Success`. Поэтому
`unity-client/Tools/build-windows.ps1` обязан сначала импортировать чистую
копию проекта в ASCII-путь; сборщик считает сообщения
`Script attached ... is missing` фатальными.

## Зелёные проверки не означают работающий клиент

`npm run check` проверяет сервер (юнит-проверки модулей `src/server/` и сценарии
на настоящем `server.js` с изолированным `DATA_DIR`), авторские данные, ассеты и
паритет клиента с сервером по событиям и каталогам. Поведение и вёрстку
Unity-клиента он не видит: экран можно сломать при всех зелёных проверках.
Клиент проверяют редакторские пробы, batch-аудит `RoaClientAuditRunner.Run` и
снимки экранов из проб.

## Компиляция C# и пробы Unity не выполняются в CI

`.github/workflows/checks.yml` запускает только `npm run check` на Linux-раннере
без Unity. Ни `npm run check:unity-csharp`, ни
`unity-client/Tools/compile-check.ps1`, ни редакторские пробы в CI не попадают;
путь к установке Unity в `compile-check.ps1` задан по умолчанию под одну машину
(параметр `-UnityData`). Регрессия клиента может дойти до релиза, оставаясь
«зелёной».

План устранения долга и критерии готовности перечислены в
[ROADMAP.md](ROADMAP.md).
