# Roadmap

Здесь перечислена только незавершённая работа. Выполненные изменения фиксируются в [CHANGELOG.md](CHANGELOG.md), а текущее устройство систем — в тематических страницах wiki.

## P1 — общие игровые системы

### Вынести здания в data-driven framework

Правила стен, roof cells, interior objects, LOS и cutaway сейчас привязаны к торговому дому.

Критерии готовности:

- здание описывается единым реестром volumes, roof cells, portals и interior entities;
- торговый дом работает через этот реестр без отдельной параллельной логики;
- через тот же API собрана как минимум ещё одна авторская постройка;
- коллизии, LOS и крыша проверены на desktop и mobile landscape.

### Завершить авторские правила видимости и коллизий

Нужно привести крупные объекты к текущей вложенной схеме `vision` и убрать неявные fallback-решения там, где они влияют на движение, укрытие или LOS.

Критерии готовности:

- gameplay-значимые объекты явно используют `vision.mode` или `vision.blocks`;
- валидатор сообщает неизвестный режим, несовместимую collision/vision-комбинацию и пропущенное обязательное правило;
- каталог коллайдеров пересобирается только через `npm run build:colliders`;
- проходят `npm run check:movement`, `npm run check:assets` и `npm run check:data`.

### Завершить серверную терминологию профиля

Игровой интерфейс всё ещё местами называет серверный профиль «сохранением».

Критерии готовности:

- пользовательские статусы используют «профиль», «персонаж» и «синхронизация с сервером»;
- слово «сохранить» остаётся только там, где обозначает явное действие пользователя, например установку нового пароля;
- внутренние имена API и функций можно менять отдельно, без несовместимого сетевого перехода.

## P1 — производительность и наблюдаемость

Нужно закрепить последние исправления задержек сервера измеримыми проверками, а не только поиском фрагментов исходника.

Критерии готовности:

- smoke-нагрузка измеряет задержку `networkPing` при активной комнате и фоновой симуляции;
- обычные пустые комнаты спят, а encounter/battle-комнаты завершают обязательную симуляцию;
- тяжёлые обходы глобального состояния и создание комнат выполняются только для подходящего игрока;
- пороги и интервалы описаны рядом с production-настройками и проверяются после изменения.

## P2 — защита документации от дрейфа

Критерии готовности:

- индекс wiki содержит настоящие относительные Markdown-ссылки;
- автоматическая проверка находит отсутствующие локальные цели и повреждённые якоря;
- актуальные страницы не превращаются в патчлог, а старые записи явно помечены архивом;
- версия и ключевые инварианты wiki сверяются с `package.json` и действующими проверками.

## Общие правила приёмки

- Итерировать через самый узкий подходящий `npm run check:*`.
- Перед передачей существенного изменения выполнять `npm run check`.
- Для networking дополнительно проверять `/health` и реальное Socket.IO-соединение.
- Визуальные и интерактивные изменения проверять в браузере на desktop и mobile landscape.
- Не изменять уникальные ID глобальных точек и не записывать runtime-состояние в `data/`.
