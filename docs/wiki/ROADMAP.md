# Roadmap

Здесь перечислена только незавершённая работа. Выполненные изменения фиксируются в [CHANGELOG.md](CHANGELOG.md), текущее устройство систем — в тематических страницах wiki, состояние KRM-задач — в [состоянии внедрения](../KROMKA_IMPLEMENTATION_STATUS.md).

## P1 — экономика v3 (KRM-22)

Этапы «одного крана» выполнены: снаряжение приходит в мир только из крафта игроков, синь и марки лежат на счёте аккаунта, опасные клетки и A-Life работают. Остаётся платёжный магазин сини.

## P1 — Unity-поставка

### Довести WebGL до полной production-готовности

Unity WebGL — основная поставка для игроков, но часть путей не проверена.

Критерии готовности:

- игра проверена на реальном мобильном телефоне (touch, клавиатура в
  `InputField`, производительность);
- https/brotli проверены на production-домене, включая нативную отдачу `.br`;
- длинная сессия (1+ час) не показывает неограниченный рост памяти;
- при необходимости подключены SDK целевых площадок.

## P1 — общие игровые системы

### Вынести здания в data-driven framework

Загрузчик локаций собирает отдельные объекты и пакетирует модульные части, но
завершённого контракта здания в данных пока нет.

Критерии готовности:

- здание описывается единым реестром volumes, roof cells, portals и interior entities;
- первая законченная постройка работает через этот реестр без отдельной параллельной логики;
- через тот же API собрана как минимум ещё одна авторская постройка;
- коллизии, LOS и крыша проверены на desktop и mobile landscape.

### Завершить авторские правила видимости и коллизий

Нужно привести крупные объекты к текущей вложенной схеме `vision` и убрать неявные fallback-решения там, где они влияют на движение, укрытие или LOS.

Критерии готовности:

- gameplay-значимые объекты явно используют `vision.mode` или `vision.blocks`;
- валидатор сообщает неизвестный режим, несовместимую collision/vision-комбинацию и пропущенное обязательное правило;
- каталог коллайдеров пересобирается только через `npm run build:colliders`;
- проходят `npm run check:movement`, `npm run check:assets` и `npm run check:data`.

## P1 — производительность и наблюдаемость

Нужно закрепить исправления задержек сервера измеримыми проверками.

Критерии готовности:

- smoke-нагрузка измеряет задержку `networkPing` при активной комнате и фоновой симуляции;
- обычные пустые комнаты спят, а encounter/battle-комнаты завершают обязательную симуляцию;
- тяжёлые обходы глобального состояния и создание комнат выполняются только для подходящего игрока;
- пороги и интервалы описаны рядом с production-настройками и проверяются после изменения.

## P2 — защита документации от дрейфа

Критерии готовности:

- автоматическая проверка находит отсутствующие локальные цели ссылок, несуществующие пути, npm-скрипты и классы в `.md`;
- версия и ключевые инварианты wiki сверяются с `package.json`.

## P2 — идеи зон мира

- Экран аванпостов и событий на глобальной карте с фильтром по фракции и
  таймерами. В экране рынка остаются поиск по названию товара и история цен.
- Дополнительные шаблоны публичных событий (караван-ловушка, разрушенная
  лаборатория) и сезонные модификаторы рождения артефактов.
- Гарнизоны с профилями фракций и подкрепление по логистике маршрутов.
- Мобильная раскладка панели мировых событий как отдельный компактный режим.

## Правила приёмки

Общие для всех задач — в [`AGENTS.md`](../../AGENTS.md): узкая проверка во время
работы, `npm run check` перед передачей, для Unity — `compile-check.ps1`, пробы
и `npm run check:unity-parity`, визуальные изменения — в собранном клиенте на
desktop и в mobile landscape.
