# Макет площадки места — `roa.siteLayout.v1`

Макет (`data/kromka/site-layouts/<id>.json`) — единственный вход сборки площадки места в сцене
сектора. Его читают два инструмента:

- `node tools/site-apply.js data/kromka/site-layouts/<id>.json` — пишет в данные зоны строку площадки,
  тайники, живые строки NPC, строки объектов с именем/целью, убирает портал места и всё, что
  конструктор зоны положил под площадку;
- Unity `Kromka.EditorTools.KromkaSiteBuilder.RunBatch` (env `ROA_SITE_LAYOUT`) — ставит модели
  PolygonApocalypse в сцену сектора, режет их коллизию, экспортирует сцену и снимает кадры в
  `Build/sites/<id>/renders/` (`top.png` сверху с сеткой 5 м, `game-*.png` игровой камерой,
  `mobile-center.png`, `build-report.json`).

## Оси

Все координаты объектов, NPC, тайников и точек — **метры в осях площадки**: начало — центр
площадки, +X — её «восток», +Z — её «север» (при `rotationY: 0` совпадают с осями мира: север
= +Z, восток = +X). `rotY` — поворот объекта вокруг вертикали в градусах, **по часовой стрелке
при взгляде сверху** (как Unity): 0 — «лицом» (+Z модели) на север, 90 — на восток, 180 — на юг,
270 — на запад. Земля плоская, `y = 0`; `y` > 0 — поставить на что-то (мешки на контейнер).

## Поля

```jsonc

  "site": {

    "name": "Застава 17",
    "kind": "outpost",
```

## Правила сборки

- **Только модели пака** `Assets/Synty/PolygonApocalypse/Prefabs`, по точному имени из
  `Build/sites/polygon-catalog.tsv` (колонки: имя, категория, размер X, размер Z, высота,
  centerX/centerZ — где центр габарита относительно опоры модели при `rotY: 0`, minY — низ
  модели, коллайдеры, лист превью, клетка). Пример: `SM_Bld_Bunker_Wall_Concrete_x2_01` —
  5,01 × 0,25 м, centerX −2,5: опора на восточном торце, стена тянется на запад. Листы превью — `unity-client/Library/PolygonCatalog/<лист>.png`
  (8 колонок × 6 рядов, клетка — номер слева направо, сверху вниз, с 0); смотри только нужные.
- **Масштаб не меняется никогда** (поля `scale` нет) — не подходит по размеру, бери другую модель.
- Для Дамбового проезда поле `clearRiver` удаляет из сцены все старые объекты зоны,
  если их опора попала в русло Тесьмы или в полосу `margin` метров от берега.
  Профиль берега общий с клиентом и сервером.
- **Габарит и опора.** Размер в каталоге — габарит модели при повороте 0; опора модели обычно у
  земли в её центре или углу — смотри превью. Модель с `minY` сильно ниже нуля (лотки StormCanal,
  низ −2,5 м) на ровной земле почти не видна.
- **Коллизия автоматическая**: коллайдеры модели режутся на высоте тела (0,2–1,75 м) в коробки
  25 см — их видит и сервер, и клиент. Всё, что выше 0,2 м, станет стеной; плоское (плиты,
  дорожная разметка, декали) — проходимо. Для навесов, проводов, флагов над головой ставь
  `collision: "none"`. Модели без коллайдеров не мешают никому.
- **Проходы**: не уже 2,5 м (главный — 4 м) между коробками коллизии; игрок — капсула радиусом
  ~0,35 м. Ни одна точка NPC, тайника или выхода не должна оказаться внутри коллизии или в тупике.
- **Обзор**: `auto` — выше 1,8 м закрывает обзор, 0,5–1,8 м — низкое укрытие. Можно переопределить.
- **NPC** стоят по точкам макета; именной (`named: true`) — только из `data/kromka/npcs.json`.
  Облик (`appearance`) и снаряжение (`equipment`) — ключами игры (смотри живые строки NPC в
  `data/locations/*.json`, например `coreBaseUprava.json`).
- **Тайники**: `tier` из `data/loot-tables.json` → `containers` (survival, tools, medical, ammo,
  wasteland, rare, basic); лут — авторский список по правилам `docs/wiki/WORLD_CONTAINERS_SYSTEM.md`
  (снаряжения нет, марки только за замком и не в мирной зоне).
- **Бюджет**: до ~160 объектов; мелочь — группами у стен, а не россыпью по проходам.
