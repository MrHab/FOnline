# Авторское размещение мест мира

Для мира `kromka-1` места заданы вручную: узлы `nodes` в `data/global-map.json`
с теми же координатами, что у точек `locations` в
`data/kromka/world-layout.seed.json`, связанные с лорным каталогом
`data/kromka/locations.json` и сценами мест Unity. `data/global-map.json`
помечена `sitePlacement: unity-authored` — признак авторского, а не
процедурного размещения; сервер выводит его и из самой ревизии, поэтому файл
Кромки без поля тоже не включает процедурную генерацию
(`src/server/authored-world-sites.js`).

Узел места определяет, в какой зоне мира оно стоит и где в ней портал: граф зон
(`tools/build-zone-graph.js`) кладёт каждое место в зону его точки.

## Разделение ответственности

- Автор задаёт стабильный ID, сцену и точку места. Сервер сохраняет точные
  координаты, включая ноль и дробные значения; привязки к центрам клеток нет.
- Лорный каталог задаёт назначение, макрорегион и описание локации.
  Названия активных мест симуляции также берутся из этого каталога, а не из
  прежних процедурных шаблонов.
- Сервер управляет состоянием существующих мест: ресурсами, контролем,
  населением, конфликтами, заданиями и снабжением. Он не выбирает новые места
  для районных точек интереса и не переставляет их каждые 72 игровых часа.

В мире 44 места, четыре из них скрытые (`hidden: true`) — базы Сердцевины: в
зоне у них нет портала, туда попадают по контракту. Записи симуляции привязаны
к этим узлам; стабильные служебные ID ресурсов могут отличаться от ID сцены
места. Остальные узлы обслуживаются отдельными системами сюжетных комплексов и
клановых баз. Не нужно создавать дополнительную случайную точку для каждой
клетки или сектора.

## Рабочий процесс

1. Создать/изменить лорную запись и связанную сцену места.
2. Поставить или сдвинуть точку места одинаково в `data/kromka/world-layout.seed.json`
   (`x`/`z`) и в `nodes` файла `data/global-map.json` (`x`/`y`). Для новой
   локации согласовать её стабильный ID с каталогом и seed.
3. `node tools/build-kromka-runtime-world.js --sync-authored` обновляет
   производный `data/generated/kromka/world.json`, не трогая карту.
4. `npm run build:zone-graph` пересобирает граф зон: место встанет в зону своей
   точки.
5. Проверить `npm run check:authored-world-sites`, `npm run check:kromka-world` и
   `npm run check:zones`.
6. Перезапустить локальный сервер. Деплой остаётся ручным.

Свободное размещение через `upsertSite` и `/api/dev/wasteland/site` для этого
мира запрещено: при `sitePlacement: unity-authored` endpoint отвечает 409.
Процедурная логика размещения осталась только для карт без этого признака и их
тестов, не для основной карты Кромки.

## Миграция старой симуляции

При загрузке или синхронизации карты неразмещённые/процедурные записи выводятся
из активной симуляции. Оригиналы сохраняются в `retiredWorldSites` внутри
runtime-сохранения: точки с запасами и конфликтами, зависимые партии, задания,
зоны и перевозки. Повторная загрузка не создаёт архив повторно и не возрождает
случайные точки. Архив не экспортируется в авторские JSON и не публикуется
как активные места карты.

Учётные записи, инвентари персонажей, история выполненных заданий и определения
лорных локаций не переписываются этой миграцией. Архивные активности больше
не продолжаются в старых случайных местах; их данные доступны для восстановления
или отдельного авторского переноса. Существующий обработчик входа использует
Ключи как резервную локацию, если сохранённого места больше нет.

## Что проверяет `check:authored-world-sites`

- `data/global-map.json` помечена `unity-authored`, ID узлов уникальны, а файл
  ревизии `kromka-1` не может вернуться к процедурному размещению;
- у каждого узла есть лорная запись и существующая Unity-сцена места;
- серверный нормализатор карты сохраняет дробные координаты;
- генератор районных точек не сканирует сетку и ничего не создаёт даже на
  больших игровых интервалах.
