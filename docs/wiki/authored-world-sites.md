# Авторское размещение мест на глобальной карте

Для мира `kromka-1` источником размещения являются объекты
`KromkaWorldLocationAuthoring` в сцене
`Assets/Scenes/Kromka/KromkaGlobalMap.unity`, связанные с лорным каталогом
`data/kromka/locations.json` и локальными Unity-сценами.
`data/global-map.json` помечена `sitePlacement: unity-authored`; сервер выводит
этот признак и из самой ревизии, поэтому файл Кромки без поля тоже не включает
процедурную генерацию (`src/server/authored-world-sites.js`).

## Разделение ответственности

- Unity задаёт стабильный ID, сцену и положение места. Экспорт сохраняет точные
  координаты, включая ноль и дробные значения; привязки к центрам клеток нет.
- Лорный каталог задаёт назначение, макрорегион и описание локации.
  Названия активных мест симуляции также берутся из этого каталога, а не из
  прежних процедурных шаблонов.
- Сервер управляет состоянием существующих мест: ресурсами, контролем,
  населением, конфликтами, заданиями и снабжением. Он не выбирает новые места
  для районных точек интереса и не переставляет их каждые 72 игровых часа.
- Движение караванов и встречи движущихся участников не являются генерацией
  постоянных мест; эти отдельные игровые механики не отключены.

На текущей карте 44 узла, четыре из них скрытые (`hidden: true`) — базы
Сердцевины, к которым ведёт контракт, а не метка карты. Записи симуляции
привязаны к этим узлам; стабильные служебные ID ресурсов могут отличаться от ID
локальной сцены. Остальные узлы обслуживаются отдельными системами сюжетных
комплексов и клановых баз. Не нужно создавать дополнительную случайную точку
для каждой клетки или сектора.

## Рабочий процесс

1. Создать/изменить лорную запись и связанную локальную сцену.
2. Разместить соответствующий маркер в авторской глобальной Unity-сцене.
   Для новой локации согласовать её стабильный ID с каталогом и world-layout seed.
3. Экспортировать глобальную карту из Edit Mode. Экспорт проверяет уникальность
   маркеров, существование сцены и лорной записи, границы карты.
4. Проверить `npm run check:authored-world-sites` и `npm run check:kromka-world`.
5. Перезапустить локальный сервер для загрузки экспорта. Деплой остаётся ручным.

Свободное размещение через `upsertSite` для этого мира запрещено: при
`sitePlacement: unity-authored` симуляция отказывает с ошибкой.
Процедурная логика размещения осталась только для карт без этого признака и их
тестов, не для основной карты Кромки.

## Миграция старой симуляции

При загрузке или синхронизации карты неразмещённые/процедурные записи выводятся
из активной симуляции. Оригиналы сохраняются в `retiredWorldSites` внутри
runtime-сохранения: точки с запасами и конфликтами, зависимые партии, задания,
зоны и перевозки. Повторная загрузка не создаёт архив повторно и не возрождает
случайные точки. Архив не экспортируется в авторские JSON и не публикуется
как активные места карты.

Учётные записи, инвентари персонажей, история выполненных заданий и определения
лорных локаций не переписываются этой миграцией. Архивные активности больше
не продолжаются в старых случайных местах; их данные доступны для восстановления
или отдельного авторского переноса. Существующий обработчик входа использует
Ключи как резервную локацию, если сохранённого места больше нет.

## Что проверяет `check:authored-world-sites`

- `data/global-map.json` помечена `unity-authored`, ID узлов уникальны, а файл
  ревизии `kromka-1` не может вернуться к процедурному размещению;
- у каждого узла есть лорная запись и существующая локальная Unity-сцена;
- серверный нормализатор карты сохраняет дробные координаты Unity;
- генератор районных точек не сканирует сетку и ничего не создаёт даже на
  больших игровых интервалах.
