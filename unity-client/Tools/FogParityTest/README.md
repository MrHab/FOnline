# Проверка паритета тумана войны

Самодостаточное консольное приложение .NET 8: ни Unity, ни сервер, ни файлы
проекта ему не нужны. В `Program.cs` лежат две независимые реализации одних и
тех же правил видимости на голых массивах. Обе гоняются по одним и тем же
случайным картам (seed зафиксирован), ответы сравниваются потайлово.

- **Эталон** (методы `Ref*`) — эталонная запись правил: набор видимых тайлов
  лучами Брезенхэма, строгая линия видимости, правило «присевший скрыт низким
  укрытием» (то же, что серверное `isCrouchedTargetHiddenBehindLowCover()`) и
  тайловая баллистика `roomBlockingDistanceOnRay()` из `server.js`.
- **Порт** (методы `Port*`) — копия кода `Assets/Scripts/Game/RoaFogOfWar.cs`:
  `MarkRay`, `HasStrictLineOfSight`, `HiddenByLowCover` и
  `TerrainBlocksBallisticLine` вместе с инверсией оси Z Unity.

Исходники клиента программа не читает. После правки этих методов в
`RoaFogOfWar.cs` копию в `Program.cs` нужно обновить вручную, иначе тест
продолжит проверять прежний код.

Блок «точные OBB» сверяет две копии лучевого теста по повёрнутому
прямоугольнику. В `RoaFogOfWar.cs` такого теста нет — видимость клиента
тайловая, — поэтому этот блок проверяет только согласованность самих копий.

```bash
dotnet run -c Release --project unity-client/Tools/FogParityTest
```

Ожидаемый вывод: 460 800 запросов видимости, 120 000 лучей по OBB и 120 000
тайловых баллистических лучей, ноль расхождений, код возврата 0.

## Что именно он ловит

Тест намеренно допускает наблюдателя, стоящего **на тайле низкого укрытия**:
такой тайл не закрывает клетку для движения, и это не искусственный случай.
Линия тайлов между наблюдателем и целью не включает тайл самого наблюдателя —
иначе игрок, стоящий на ящике, прятал бы от себя всех присевших соседей.

Тест падает и тогда, когда ветка низкого укрытия, пересечение OBB или
баллистическая блокировка не сработали ни разу: иначе он «прошёл бы», ничего не
проверив.
